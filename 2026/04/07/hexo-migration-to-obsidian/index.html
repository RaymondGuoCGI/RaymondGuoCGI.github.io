    从 /root/Hexo_Blog_Raymond 到 Obsidian：如何实现 Hexo 博客的完美自动化同步

    很多 Hexo 用户最初都习惯将博客托管在 VPS 的 /root\ 目录下。但随着工作流的进化，我们发现这种方式存在严重的局限性：无法实现本地实时编辑、多端同步困难、以及备份风险。

    昨天，我正式完成了从 /root/Hexo_Blog_Raymond\ 到 Obsidian 仓库的 搬家工程。以下是这次自动化同步实战的核心步骤：

    1. 为什么要迁移？

    • 笔记即博文：利用 Obsidian 强大的编辑体验，直接在笔记库中撰写 Markdown。
    • 自动化 Git 同步：利用 Obsidian Git 插件或定时任务，实现本地与 VPS 的无缝对接。
    • SEO 规范化：借此机会修复了 \sitemap.xml\ 和 \canonical\ 标签的配置错误。

    2. 核心同步逻辑

    我们放弃了繁琐的 \scp\ 传输，转而采用以下架构：

    1. 本地/VPS 双向仓库：将 Hexo 源码文件夹直接置于 Obsidian 的一个子目录中。
    2. SSH 密钥授权：打通本地电脑、VPS 与 GitHub 之间的 SSH 免密通道。
    3. 自动化部署：在 VPS 上通过一条指令完成 \hexo clean && hexo g && hexo d\。

    3. 遇到的坑与解决方法

    在迁移过程中，最容易出现的问题是文件名乱码（由于字符集转换）和链接降权。通过设置 _config.yml\ 中的 \url\ 为 \https://raymondstudio.cn\，并强制生成规范的 Sitemap，我们成功让 Google 认准了主站。

    总结

    这次迁移不仅是一次技术重构，更是对个人知识库的一次深度集成。现在，每一篇在 Obsidian 中写下的灵感，都能瞬间化为公网上的博文。
